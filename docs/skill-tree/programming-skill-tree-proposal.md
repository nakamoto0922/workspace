# プログラミング学習用スキルツリーアプリ 提案書

## 1. 概要

本提案は、プログラミング学習を「スキルツリー」の形で可視化し、学習者が小さな目標を順番に達成しながら新しいスキルを習得できる Web アプリケーションの企画である。

一般的な ToDo リストや学習記録アプリは、単発のタスク管理や履歴管理には向いている一方で、学習全体の構造や前提関係が見えにくいという課題がある。  
本アプリでは、学習内容をツリー状に整理し、各ノードを「達成すべき小目標」として扱うことで、学習の順序・依存関係・全体像を把握しやすくする。

本アプリの目的は、成長を厳密に数値化することではなく、**新しいスキルを習得するための道筋を整理し、目標を一つずつ潰していける状態を作ること**にある。

---

## 2. 背景と課題

プログラミング学習では、以下のような課題が発生しやすい。

- 何から手をつければよいかわからない
- 今やっている内容が、最終的にどのスキルにつながるのか見えにくい
- 学習項目同士の前提関係が把握しづらい
- 途中で「これも必要だった」と気づいて学習計画が崩れる
- 単純な ToDo リストでは、構造的な学習管理に限界がある

特にプログラミングは、学習を進めるほど「この知識が前提だった」「この単元はもっと細かく分けるべきだった」といった再構成が頻繁に発生する。  
そのため、最初から固定された学習リストではなく、**後から柔軟に編集できる学習マップ**が望ましい。

---

## 3. 解決したいこと

本アプリでは、以下を実現したい。

- 学習したいテーマをツリー状に整理する
- 各ノードを「習得のための小目標」として定義する
- 小目標を達成することで、次の学習項目が解放される
- 全体の学習構造と、今やるべきことの両方を見える化する
- 後からノードの追加・分割・移動ができるようにする

これにより、単なるタスク管理ではなく、**構造化された学習の進行管理**を目指す。

---

## 4. アプリのコンセプト

### コンセプト
**「プログラミング学習を、ツリー型のロードマップとして進めるアプリ」**

本アプリでは、ノードは現在の能力値や経験値ではなく、**達成すべき具体的な学習目標**を表す。

例えば React を学ぶ場合、以下のような構成を想定できる。

- JavaScript基礎
  - 配列メソッドを使える
  - 非同期処理を理解する
- React基礎
  - props を使ったコンポーネントを作る
  - useState で状態を持つ
- React応用
  - API 通信して結果を表示する
  - フォームを作る

このように、抽象的な「Reactを理解する」ではなく、**チェック可能な小目標**に落とし込むことで、達成のしやすさと学習の見通しを両立する。

---

## 5. 想定ユーザー

- プログラミングを独学している人
- 学習計画を整理したい人
- 学習全体の構造を見ながら進めたい人
- 既存の ToDo リストでは物足りない人
- 「何を学ぶか」だけでなく「どうつながっているか」も把握したい人

特に、自分用の学習マップを育てながら使う個人用途との相性が良い。

---

## 6. 主要な価値

### 6.1 学習順序が見える
ノード同士の前提関係を持たせることで、「今やるべきこと」と「その次にやること」が明確になる。

### 6.2 小目標に分解できる
大きなテーマを小さな達成単位に分けることで、着手しやすくなる。

### 6.3 学習全体の構造を把握できる
単発のタスクではなく、学習テーマ全体の地図として見ることができる。

### 6.4 あとから再構成できる
「このノードをもっと細かくしたい」「途中にこれを挟みたい」といった変更に対応しやすい。

### 6.5 ToDo とロードマップを両立できる
ツリーは全体図として使い、現在着手可能なノードを抽出して ToDo として扱える。

---

## 7. 想定機能

### 7.1 ツリー表示
- ノードをツリー状に表示する
- ロック / 解放 / 完了状態が分かる
- 前提関係が視覚的に分かる

### 7.2 ノード詳細表示
- ノードの説明
- 達成条件
- 前提ノード
- 関連メモ
- 参考リンク

### 7.3 ノード完了管理
- ノードを手動で完了にできる
- 一定条件で上位ノードの進捗が進む
- 条件を満たした子ノードが解放される

### 7.4 「今やること」抽出
- 現在着手可能なノードのみを一覧表示する
- 実質的な ToDo リストとして利用できる

### 7.5 ノード編集
- ノード追加
- ノード分割
- ノード統合
- ノード移動
- 前提関係の追加 / 変更

---

## 8. 本アプリの特徴

本アプリは、以下の点で一般的な学習管理アプリと異なる。

### 一般的な ToDo リスト
- 単発タスクの管理が中心
- 学習項目同士の関係が見えにくい

### 一般的な学習記録アプリ
- 何をやったかの記録が中心
- 今後何をやるべきかの構造が弱い

### 本アプリ
- 学習項目の構造化が中心
- ノードは「成長記録」ではなく「小目標」
- ツリーを編集しながら学習計画自体を育てられる

---

## 9. 進め方の方針

最初から大規模な仕組みを作るのではなく、小さな実装から始める。

### 初期段階で重視すること
- ノードを小目標として扱うこと
- ツリー全体を見られること
- 現在できることが分かること
- あとから構造を変更しやすいこと

### 初期段階で捨てるもの
- 厳密な成長分析
- 自動での習熟度判定
- 複雑な経験値システム
- 外部サービスとの高度な連携

---

## 10. 最小実装のイメージ

まずは以下を満たす最小構成を想定する。

- ノードを表示できる
- ノードの状態を管理できる
  - locked
  - available
  - completed
- ノードをクリックして詳細を見られる
- ノードを手動で完了にできる
- 完了によって次のノードが解放される
- 現在着手可能なノードを一覧化できる

この時点で、すでに「ツリー型プログラミング学習 ToDo アプリ」として成立する。

---

## 11. 今後の拡張余地

- 分割 / 統合しやすいノード編集UI

- 振り返りビュー

ただし、これらは初期実装の後に段階的に検討する。

---

## 12. まとめ

本アプリは、プログラミング学習を「スキルツリー型のロードマップ」として扱うことで、学習の全体像と小さな達成目標の両方を可視化することを目指す。

重要なのは、能力を数値化することではなく、**何を習得したいか、そのために何を順番に潰していくかを整理できること**である。

また、プログラミング学習では途中で構造の見直しが必ず発生するため、固定的な学習ツリーではなく、**あとから柔軟に追加・分割・移動できる学習マップ**として設計することが重要である。

この方針により、単なる ToDo 管理ではなく、実際の学習プロセスに寄り添った、使い続けられるツールになることが期待できる。
